# MCTS 侧消融结果解读

## 1. 使用定位

本文档不追求罗列全部原始字段，而是从论文读者最关心的三个角度来解读当前结果：

- **效果是否变差？**
- **效率是否变差？**
- **哪些结论已经足够稳定，哪些还要等 official？**

当前最可靠的主证据来自 `pilot`，`smoke` 主要用于验证方向一致性。

## 2. pilot 真值聚合结果

### 2.1 `HOMO(D)`

| `wo_leaf_value` | `0.4896` | `0.95` | `204.35` | `188.25` | **效果大幅退化**，且成本暴涨 |
| `random_topb` | `1.6479` | `0.95` | `3.62` | `8.80` | 效果低于 `full`，也更慢 |

| variant | improvement | success rate | runtime | expanded nodes | 相对 `full` 的解读 |
| --- | ---: | ---: | ---: | ---: | --- |

## 3. 从论文角度如何读这些数

### 3.1 `wo_leaf_value`：这是当前最强的负面对照

这个变体最重要，因为它已经不是“略差”，而是出现了**结构性退化**：

- 在 `HOMO(D)` 上，平均改善从 `2.0041` 下降到 `0.4896`，下降约 `75.6%`；
- 同时 runtime 从 `2.31` 飙到 `204.35`，约为 `88.4x`；
- expanded nodes 从 `7.60` 上升到 `188.25`，约为 `24.8x`。

这说明 `leaf value` 并不是一个“锦上添花”的模块，而是当前框架中**实质性决定搜索质量与搜索效率的关键组件**。

在 `LUMO(U)` 上，`wo_leaf_value` 的 improvement 表面上略高于 `full`，但这并不支持“去掉 leaf value 更好”这样的说法，原因有两点：

1. runtime 与 expanded nodes 分别放大到 `20.9x` 与 `16.7x`；
2. `start_count_mean = 19`，低于 `full` 的 `20`，说明该结果本身并不是完全同口径覆盖。

因此，从论文写作角度，更稳妥的表述是：**去掉 leaf value 会显著破坏搜索效率，并在至少一个主任务上显著损害最终优化质量。**

### 3.2 `wo_prior`：方向稳定，但幅度小

`wo_prior` 的特点是：

- 两个任务上都没有赢过 `full`；
- 但差距很小；
- 同时运行成本略低。

这说明 prior 对当前框架是**有帮助但并不决定性**的组件。更准确地说，prior 更像是在“相似总预算下帮助搜索更稳地走向更优区域”，但它的重要性暂时没有 `leaf value` 那么强。

从论文论证角度，这类结果适合写成：

- `prior` 带来**一致但温和的正向贡献**；
- `leaf value` 才是当前 MCTS 侧性能差异的主要来源。

### 3.3 `random_topb`：当前更像效率消融，而不是效果消融

`random_topb` 在当前证据下的特征是：

- `HOMO(D)` 上持续低于 `full`；
- `LUMO(U)` 上在 smoke 中曾短暂高于 `full`，但到了 pilot 反而低于 `full`；
- runtime 与 expanded nodes 在两个任务上都明显高于 `full`。

因此，这个变体当前更适合支持如下说法：

- OFO 引导的 expansion ranking **至少明显改善了搜索效率**；
- 至于它是否稳定改善最终改善值，现阶段证据还不如 `leaf value` 那么强。

## 4. smoke 与 pilot 的一致性价值

### 4.1 一致的部分

- `wo_leaf_value` 在两个任务、两轮实验中都比 `full` 更差，尤其在 `HOMO(D)` 上退化非常稳定；
- `wo_prior` 在两轮中都与 `full` 接近；
- `random_topb` 在效率上都显著更差。

### 4.2 不一致的部分

- `random_topb` 在 `LUMO(U)` smoke 中 improvement 一度高于 `full`，但 pilot 中反转；
- `wo_leaf_value` 在 `LUMO(U)` 上 improvement 也没有直接下降。

这说明：

- **单看 improvement 不够**；
- 必须把 runtime 与 expanded nodes 一起纳入判断；
- 也说明为什么 `official` 多 seed 仍然有必要。

## 5. 当前已经可以下的结论

### 5.1 强结论

1. **`leaf value` 是当前框架中的关键组件。**
2. **去掉 `leaf value` 会显著恶化整体性能，尤其是效率，并在 `HOMO(D)` 上明显损害优化质量。**
3. **当前完整框架至少优于一个关键消融版本（`wo_leaf_value`）。**

### 5.2 中等强度结论

1. **`prior` 的贡献方向是正向的，但量级较小。**
2. **随机替代 expansion ranking 会稳定降低搜索效率。**

### 5.3 暂时不要写死的结论

1. 不要写“所有消融版本都明显更差”；
2. 不要写“random top-b 在所有任务上都显著降低最终改善值”；
3. 不要写“prior 是与 leaf value 同等重要的核心来源”。

## 6. 当前最推荐的主文口径

如果今天就要组织正文，当前最稳的写法是：

> 我们在 `LUMO(U)` 与 `HOMO(D)` 上对 MCTS 侧关键组件进行了真值消融。结果表明，`leaf value` 是当前框架中最关键的搜索信号：移除该项后，`HOMO(D)` 上的平均改善由 `2.0041` 降至 `0.4896`，同时平均搜索时间与展开节点数分别增加到原始配置的 `88.4x` 与 `24.8x`。相比之下，移除 `prior` 仅带来较小幅度退化，说明其贡献更偏向温和的搜索引导；而将 expansion ranking 随机化则主要损害搜索效率，其对最终改善值的影响目前仍表现出一定任务依赖性。

## 7. 一句话总结

当前 MCTS 侧消融最有力的结论不是“每个模块都同样关键”，而是：**`leaf value` 是决定当前框架有效性的关键组件，`prior` 与 expansion ranking 则表现为较弱或更偏效率侧的贡献。**
