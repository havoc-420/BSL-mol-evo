# OFO 论文主线与行文思路

## 1. 核心主张

这套工作最稳的论文主线不是“做了很多模型尝试”，而是围绕一个清晰论点展开：**将单步分子编辑响应预测建模为一个显式的条件回归问题，并进一步把该局部响应模型嵌入树搜索，以支持多步分子优化。**

因此，全文不宜写成“版本演进记录”，而应写成一条递进式论证链：

1. **问题层**：多步分子优化困难，原因在于化学空间巨大、离散编辑组合爆炸、局部编辑效果难以可靠评估；
2. **方法层（一）**：提出 OFO，将一次分子编辑前后的结构差异与操作语义映射到性质变化量；
3. **方法层（二）**：将 OFO 作为局部转移评价器、先验构造器和叶节点评估器，嵌入 MCTS，形成多步优化框架；
4. **验证层**：通过基座筛选、单步预测实验、多步优化实验、消融与案例分析，证明该路线的有效性。

## 2. 推荐的整篇论文结构

### 2.1 完整版结构（更适合毕业论文或长文）

#### Abstract
- 研究任务：分子优化与分子编辑响应预测；
- 关键缺口：现有方法要么偏静态性质预测，要么缺乏可靠的单步编辑评价机制；
- 本文方案：提出 OFO，并进一步构建 OFO-guided MCTS；
- 关键机制：双分支几何编码、编辑条件建模、单步打分驱动多步搜索；
- 结果概述：单步预测有效，多步优化收益明显。

#### 1 Introduction
对应文件：`1-intro.md`

这一章负责回答三个问题：
- **为什么分子优化重要**；
- **为什么现有路线还不够好**；
- **为什么“单步响应预测 + 树搜索”是合理路线**。

引言里建议把“局部编辑效果不可可靠量化”作为核心矛盾，而不是一上来就讲模型结构。

#### 2 Related Work
对应文件：`2-related-work.md`

建议拆成三块：
- 几何感知分子性质建模；
- 分子优化与分子编辑方法；
- 搜索式优化与 MCTS 路线。

这一章的作用不是平铺综述，而是为后文的 OFO 与 MCTS 组合框架“搭桥”。

#### 3 OFO: Single-step Molecular Editing Response Prediction
对应文件：`3-method-ofo.md`

这一章承担全文第一个方法贡献：
- 将单步编辑建模为条件回归；
- 给出输入表示、分子图、操作编码与融合预测结构；
- 解释为何该任务应该学习性质增量，而不是绝对性质。

#### 4 OFO-guided MCTS for Molecular Optimization
对应文件：`4-method-mo-mcts.md`

这一章承担全文第二个方法贡献：
- 把 OFO 从“预测器”变成“搜索中的局部价值函数”；
- 用 OFO 引导候选扩展、prior 构造、叶节点评估与回传；
- 配合深度约束、logP 约束和剪枝策略形成可控搜索。

#### 5 Experiments
对应文件：`5-experiments.md`

实验章节建议按下面顺序展开：
- **5.1 Preliminary backbone selection**：说明为何最终实例化选用某个 backbone；
- **5.2 Single-step prediction performance**：验证 OFO 的局部响应建模能力；
- **5.3 Multi-step molecular optimization**：验证 OFO-guided MCTS 的全局优化能力；
- **5.4 Ablation study**：验证几何编码、操作编码、prior 设计、剪枝机制；
- **5.5 Case study**：展示具体优化路径与分子变化实例。

其中，`history-v1/5-1-backbone-selection.md` 更适合作为 `5.1` 的基础材料，而不是放进 `Method` 主体。

#### 6 Limitations and Discussion
这一章可以并入实验末尾，也可以单列。适合讨论：
- OFO 误差在长路径中的累积影响；
- MCTS 搜索开销与分支控制的权衡；
- 当前约束设计对药化可行域的局限。

#### 7 Conclusion
对应文件：`6-conclusion.md`

结论要回收的不是零散结果，而是整条主线：
- 提出 OFO；
- 以 OFO 支持 MCTS；
- 在单步预测与多步优化上都获得正向结果。

### 2.2 压缩版结构（更适合短 paper）

如果后续要压缩为短文，可以把结构缩成：

1. Introduction
2. Related Work
3. Method
   - 3.1 OFO predictor
   - 3.2 OFO-guided MCTS
4. Experiments
5. Conclusion

这种写法下，`3-method-ofo.md` 和 `4-method-mo-mcts.md` 可以在正文合并为一个 `Method` 章节中的两个子节。

## 3. 当前最推荐的论证顺序

### 3.1 第一层：先证明“局部响应可学”

全文首先要让读者接受一个前提：**单步分子编辑造成的性质变化并不是完全不可控的黑盒噪声，而是可以通过结构对和操作条件进行建模的。**

这一步主要由 `3-method-ofo.md` 和单步预测实验支撑。

### 3.2 第二层：再证明“局部响应可用于全局优化”

在单步预测成立之后，再引出第二层论证：**如果局部编辑响应可被稳定估计，那么它就可以作为多步搜索的启发式信号。**

这时 `4-method-mo-mcts.md` 就变得自然：
- OFO 给出每一步的局部增量预测；
- MCTS 负责在多步离散编辑空间中进行层次化决策；
- 剪枝和约束负责控制搜索复杂度。

### 3.3 第三层：最后证明“这条路线优于只做静态预测或盲目搜索”

实验部分最终要回答的是：
- 只做单步预测是否足够？
- 不引入 OFO 的搜索是否会更弱？
- 几何 backbone 和搜索策略各自贡献了什么？

换言之，实验要服务于全文 claim，而不是简单堆表格。

## 4. 每个章节应该承担的功能

### Introduction
- 建立任务背景；
- 缩小问题范围；
- 明确现有缺口；
- 提出本文主线与贡献。

### Related Work
- 回顾任务侧已有路线；
- 回顾方法侧已有路线；
- 明确本文位于“单步编辑响应预测 + 搜索式优化”的交叉点。

### OFO Method
- 解决“如何对一次编辑进行建模”的问题；
- 强调条件回归、几何建模和操作语义。

### OFO-guided MCTS
- 解决“如何把单步模型用于多步优化”的问题；
- 强调 prior、value、selection、expansion 与 pruning 的统一性。

### Experiments
- 解决“方法是否有效、为何有效、哪些部分最关键”的问题；
- 注意把“基座筛选”放在实验中，而不是写成模型开发故事。

### Conclusion
- 回收全文主张；
- 给出局限与未来方向；
- 不要重复实验数字。

## 5. 写作时应坚持的几个原则

### 5.1 不写成版本演进日志

正文中尽量避免出现类似 `v0.1`、`v0.2`、`v0.3` 的叙述。论文不是项目周报，读者更关心：
- 你要解决什么问题；
- 为什么这个方法合理；
- 证据是否充分。

### 5.2 Method 与 Experiments 要分工清楚

- `Method` 负责解释最终方法本体；
- `Experiments` 负责解释为什么选择这一实例化、它表现如何、各模块贡献如何。

因此，基座模型筛选应放在实验章节，而不是放进 `3-method-ofo.md` 主体里大段展开。

### 5.3 每章只回答一个主问题

一章如果同时承担“背景、实现细节、实验解释、贡献总结”，就会显得很散。比较稳的写法是：
- 一章一个中心问题；
- 一节一个子问题；
- 一个表格或图只服务一个论点。

## 6. 现有文件与论文结构的对应关系

- `1-intro.md`：引言草稿
- `2-related-work.md`：相关工作草稿
- `3-method-ofo.md`：单步编辑响应预测方法
- `4-method-mo-mcts.md`：基于 OFO 的 MCTS 分子优化方法
- `5-experiments.md`：实验章节骨架与结果组织方式
- `history-v1/5-1-backbone-selection.md`：基座筛选与预实验比较
- `6-conclusion.md`：结论与展望草稿

## 7. 一句话版本的全文推进逻辑

**先证明单步编辑响应可以被学习，再证明它可以被用于多步搜索，最后用实验说明这种“局部响应建模 + 全局树搜索”的路线是有效且必要的。**
