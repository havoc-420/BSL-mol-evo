# OFO-MCTS 超参数试验执行计划

## 1. 目的

本计划用于补齐论文中 `OFO-guided MCTS` 的**超参数敏感性实验**，重点回答以下问题：

1. `MCTS` 的收益是否随着搜索预算增加而稳定提升；
2. `PUCT` 的探索系数是否存在稳定有效的工作区间；
3. 候选分支宽度与搜索深度如何影响改善值、成功率、多样性与运行成本；
4. 当前论文主结果是否依赖于某一组偶然参数，还是在合理范围内具有稳健性。

本计划只关注**搜索侧超参数**，不与结构消融、模块消融混在一起。模块消融（如 `w/o prior`、`w/o leaf value`）建议单列为另一组实验。

---

## 2. 实验原则

为避免变量混杂，超参数试验统一遵循以下原则：

- 固定同一个 `OFO` checkpoint，不在 sweep 过程中更换模型；
- 固定同一批起始分子集合，保证不同参数组合可直接横向比较；
- 每次只改变一个超参数，其余搜索参数保持一致；
- 主文只保留**最有解释力**的 `3` 到 `4` 组 sweep，次要参数可放附录；
- 除优化效果外，必须同时记录**运行成本**与**多样性代价**。

---

## 3. 推荐基线设置

在正式 sweep 前，先锁定一组统一的论文基线。结合当前脚本与已有结果，建议采用下列基线作为后续单因素试验的默认设置：

- `search_mode = mcts`
- `num_simulations = 800`
- `exploration_weight = 2.0`
- `max_branching = 20`
- `max_depth = 10`
- `pruning_patience = 3`
- `logp_range = [-0.5, 6.0]`
- `logp_patience = 5`
- `topK = 20`

说明：

- 上述设置与当前 `workflow-cli.md` 中的 `mcts` 示例基本一致，便于与现有实验记录对齐；
- 其中 `logp_range` 与 `logp_patience` 在本轮仅作为固定约束沿用，不纳入当前超参数 sweep 主线；
- 若最终论文主结果仍需沿用 `400/800` 两档预算，则以 `800` 作为基线更合适，因为它更接近“代表性最强”的完整搜索设置；
- 若算力不足，可准备一套“轻量基线”用于预筛：`num_simulations = 400`，其余设置不变。

---

## 4. 任务选择策略

不建议所有 sweep 都在全部任务上完整运行。建议按“**最小可行集 → 标准集 → 完整集**”三档推进。

### 4.1 最小可行集

优先选择最能体现搜索收益的任务：

- `LUMO(U)`
- `HOMO(D)`

理由：这两类任务中，`MCTS` 相比 `OFO` / `BFS` 的优势更容易显现，最适合做预算与探索系数敏感性分析。

### 4.2 标准集

在最小可行集基础上增加：

- `HOMO(U)`

理由：可进一步观察“成功率提升但多样性下降”的 trade-off 是否稳定存在。

### 4.3 完整集

若算力允许，再补：

- `LUMO(D)`

理由：该任务里单步模型本身已较强，加入它可以证明：并非所有任务都同样依赖搜索，从而让论文分析更客观。

## 5. 必做超参数试验

以下四组中，前 `3` 组建议进入主文，第四组可视算力与版面决定是否进入主文或附录。

### 5.1 搜索预算试验：`num_simulations`

#### 目标

验证 `MCTS` 收益是否随着预算增加而稳定提升，并分析收益上升区间与边际回报。

#### 建议取值

- `100`
- `200`
- `400`
- `800`
- 可选扩展：`1600`

#### 固定参数

- `exploration_weight = 2.0`
- `max_branching = 20`
- `max_depth = 10`
- 其他参数使用统一基线

#### 建议输出指标

- 平均改善值
- 改善百分比 / 成功率
- `IntDiv`
- `Morgan` 相似度
- 平均运行时间（单分子或整批）

#### 重点观察

- 性能是否随预算单调改善；
- 从 `400 -> 800` 的提升是否仍然显著；
- 更高预算是否伴随多样性下降与时间显著增加。

#### 推荐呈现形式

- 一张折线图：横轴 `num_simulations`，纵轴分别为改善值、成功率、`IntDiv`、运行时间；
- 主文中优先展示 `LUMO(U)` 与 `HOMO(D)` 两个任务。

---

### 5.2 探索系数试验：`exploration_weight`

#### 目标

验证 `PUCT` 中 exploration 与 exploitation 的平衡是否影响最终结果，并给出一个稳定有效的工作区间。

#### 建议取值

- `0.5`
- `1.0`
- `1.4`
- `2.0`
- `3.0`

#### 固定参数

- `num_simulations = 800`
- `max_branching = 20`
- `max_depth = 10`
- 其他参数使用统一基线

#### 建议输出指标

- 平均改善值
- 成功率
- `IntDiv`
- 平均运行时间

#### 重点观察

- `c` 过小时是否更容易早收敛；
- `c` 过大时是否出现探索过强、改善值下降；
- 是否存在 `1.4 ~ 2.0` 一类较稳定的有效区间。

#### 推荐呈现形式

- 一张折线图或柱状图；
- 主文可只保留 `LUMO(U)` 与 `HOMO(D)`，其余任务放附录。

---

### 5.3 分支宽度试验：`max_branching`

#### 目标

验证 OFO 候选排序是否足够有效，从而使较小分支宽度下仍能保持较好性能。

#### 建议取值

- `5`
- `10`
- `20`
- 可选扩展：`30`

#### 固定参数

- `num_simulations = 800`
- `exploration_weight = 2.0`
- `max_depth = 10`
- 其他参数使用统一基线

#### 建议输出指标

- 平均改善值
- 成功率
- `IntDiv`
- 平均运行时间

#### 重点观察

- 从 `10 -> 20` 的性能提升是否足以抵消时间成本；
- `branching` 较小时性能是否仍保持稳定；
- 是否可以支持“前置候选打分 + 截断”是有效设计，而非盲目全展开。

#### 推荐呈现形式

- 一张折线图；
- 论文分析中强调“排序质量—搜索成本”的权衡。

---

### 5.4 搜索深度试验：`max_depth`

#### 目标

验证更长编辑路径是否一定带来更好优化，并支撑误差累积与路径收益饱和的讨论。

#### 建议取值

- `2`
- `4`
- `6`
- `8`
- `10`

#### 固定参数

- `num_simulations = 800`
- `exploration_weight = 2.0`
- `max_branching = 20`
- 其他参数使用统一基线

#### 建议输出指标

- 平均改善值
- 成功率
- `IntDiv`
- `Morgan` 相似度
- 平均运行时间

#### 重点观察

- 深度增加后改善值是否持续提升；
- 是否出现“路径更长但收益趋于饱和”；
- 深度增加是否伴随误差累积、多样性下降或结构保持恶化。

#### 推荐呈现形式

- 附录优先；
- 若结果很漂亮，可主文加入一张小图并在 `discussion` 中回收。

## 9. 论文写作时的预期结论模板

若实验趋势与预期一致，正文可按以下逻辑收束：

1. **预算敏感性**：随着 `num_simulations` 增加，`MCTS` 在复杂任务上的成功率与改善值稳步提升，说明 OFO 提供的局部响应信号能够被更多搜索预算有效利用；
2. **探索系数稳健性**：过小的 `exploration_weight` 容易导致早收敛，过大则会稀释高价值分支的利用，说明 `PUCT` 需要在 exploration 与 exploitation 之间取得平衡；
3. **分支宽度权衡**：较大的 `max_branching` 能带来一定收益，但代价是运行成本上升，因此 OFO 前置排序使得有限宽度搜索成为可能；
4. **深度收益饱和**：随着 `max_depth` 增加，路径收益并非无限增长，支撑了误差累积与搜索成本增长的讨论。
