# OFO 论文按 TransDLM 行文思路的调整计划

## 1. 总体判断

当前 `docs/paper` 的整体骨架已经较为成熟，不需要推倒重写；真正需要加强的部分主要是**论证闭环**，而不是章节数量本身。

现有结构已经具备以下优点：

- `1-intro.md` 已经形成“任务背景 → 现有不足 → 本文路线”的基本主线。
- `2-related-work.md` 已经能够承接“任务侧方法 + 搜索侧方法 + 本文定位”。
- `3-method-ofo.md` 与 `4-method-mo-mcts.md` 已经形成“单步建模 + 多步搜索”的两段式方法贡献。
- `5-experiments.md` 已经具备“基座筛选 → 单步验证 → 多步验证 → 消融 → 案例”的实验框架。

因此，后续修改的目标不是重排整篇论文，而是把它进一步打磨成一篇**问题驱动、机制清楚、验证闭环明确**的成熟方法论文。

---

## 2. 全文最核心的主论点

建议全文统一围绕下面这句主论点展开，并在引言、相关工作、方法开头、实验开头、结论中反复回收：

> 现有多步分子优化方法往往侧重于评价一个分子的终态性质，却难以直接评估一次局部编辑会带来什么性质变化；而在巨大的离散编辑空间中，真正决定搜索效率的关键，恰恰是对局部编辑响应的可靠估计。因此，本文的核心不是只预测分子“好不好”，而是预测“一次编辑会带来什么变化”，并将这种局部响应转化为多步搜索信号。

围绕这句话，全文建议明确建立以下三组对照关系：

- **静态性质预测** vs **单步编辑响应预测**
- **盲目搜索/弱启发式搜索** vs **OFO 引导搜索**
- **终态评价** vs **转移级局部评价**

这会让全文从“章节上是通的”提升到“论点上是一根主轴”。

---

## 3. 需要重点加强的四个方面

### 3.1 把问题缺口写得更尖锐

目前论文已经在讲现有方法的不足，但还缺少一句可以贯穿全文的“核心缺口定义”。建议统一表述为：

- 现有方法要么依赖静态性质预测，难以评价具体编辑动作的局部收益；
- 要么依赖缺乏高质量启发式的搜索，难以在巨大离散空间中做出高效决策；
- 因而，关键问题不是只评价一个分子，而是评价“一次编辑是否值得”。

这部分应成为全文的总开场和总收束。

### 3.2 补出一层“机制/合理性分析”

相比成熟的方法论文，目前最需要补的一层，是“为什么这条路线在原理上更合理”。建议至少补清以下问题：

- 为什么预测性质增量 \(\Delta y\) 比预测绝对性质 \(y\) 更适合服务多步搜索；
- 为什么搜索更需要候选之间的**相对排序可靠性**，而不仅仅是全局回归误差更小；
- 为什么 OFO 可以自然转化为 `prior`、`expansion score` 和 `leaf value` 的统一启发式来源；
- 为什么 MCTS 能放大局部响应评分器的价值，而不是简单堆叠一个搜索模块。

如果篇幅允许，可单列成一个小节；若篇幅有限，则建议分别放在 `3-method-ofo.md` 和 `4-method-mo-mcts.md` 末尾。

### 3.3 让实验更明确地一一回应 claim

实验部分目前框架是对的，但需要从“展示结果”进一步提升到“验证论点”。建议让每一节实验都显式回答一个问题：

- `5.1`：什么 backbone 最适合承担 OFO 的单步响应建模？
- `5.2`：局部编辑响应是否真的可学？
- `5.3`：局部编辑响应是否真的能有效支撑多步全局优化？
- `5.4`：哪些模块真正贡献了性能提升？
- `5.5`：模型在真实优化路径中是如何起作用的？
- `5.6`：这条路线的边界、代价与局限是什么？

### 3.4 把“案例研究 + 局限讨论”补实

这是当前最能提升完成度的两部分。

建议：

- **案例研究** 不要只停留在框架说明，而要呈现完整优化路径：
  - 起始分子；
  - 每一步编辑动作；
  - OFO 对该步变化的预测；
  - MCTS 为什么选择该路径；
  - 最终性质如何改善。
- **局限讨论** 建议从结论中适度分离，至少单独形成实验章末尾的小节，重点讨论：
  - 长路径上的误差累积；
  - 搜索预算与效果之间的权衡；
  - 当前约束仍偏启发式，未完全等价于真实药化设计约束；
  - 多样性、可解释性、成本之间的 trade-off。

## 4. 按文件的具体调整建议

### 4.1 `1-intro.md`

**当前状态**：主线已经基本正确。

**建议调整**：

- 用一句更锋利的话概括全文问题：不是只评价分子终态，而是评价一次编辑的局部收益。
- 更明确地区分两类现有不足：
  - 静态性质预测无法回答“这一步改动值不值”；
  - 搜索方法缺少高质量局部启发式。
- 将贡献列表与后文章节显式对齐：
  - 第三章：证明局部响应可学；
  - 第四章：证明局部响应可用于多步搜索；
  - 第五章：证明这条路线有效且必要。

**目标**：让引言最后自然过渡到“单步建模 → 多步搜索 → 实验验证”的完整链条。

### 4.2 `2-related-work.md`

**当前状态**：框架是合理的。

**建议调整**：

- 在“分子优化与分子编辑方法”部分更明确指出：多数方法关注终态优化，但较少显式建模“一次编辑带来的性质响应”。
- 强调本文不是单纯换一个 backbone，而是**改变了优化建模粒度**：从分子级终态评价转向编辑级转移评价。
- 在本章结尾更自然地收束到一句定位：
  - 本文位于“编辑响应建模”与“搜索式分子优化”的交叉点上。

**目标**：让 related work 成为本文出场的“真空地带说明”，而不只是背景综述。

### 4.3 `3-method-ofo.md`

**当前状态**：内容扎实，但略偏实现展开。

**建议调整**：

- 在章节开头增加一个总体框架导语或方法总览图，明确：
  - 输入是什么；
  - 核心模块是什么；
  - 输出是什么；
  - 训练目标是什么。
- 单独增加一个小节，解释为什么建模 \(\Delta y\) 而不是直接建模 \(y\)。
- 更明确说明 `MAE` 与 `Rank Loss` 的设置不是随意选择，而是为了服务后续搜索中的“局部比较决策”。

**目标**：让第三章不仅回答“怎么做”，还回答“为什么这样建模”。

### 4.4 `4-method-mo-mcts.md`

**当前状态**：结构已经比较完整。

**建议调整**：

- 强化 OFO 与 MCTS 的统一性表达，而不是写成“先有 OFO，再把它塞进树搜索”。
- 明确 OFO 在搜索中的三种作用：
  - 候选扩展筛选；
  - 节点/动作先验；
  - 叶节点价值估计。
- 说明这三种作用共享同一套“局部响应”信号，因此是方法上的统一，而不是工程拼接。
- 若条件允许，可补一个算法框，清晰展示：
  - 输入；
  - selection；
  - expansion；
  - OFO scoring；
  - backup；
  - 输出 top-k 结果。

**目标**：让读者感觉“局部响应预测天然适合变成树搜索启发式”。

### 4.5 `5-experiments.md`

**当前状态**：骨架已经比较接近成熟论文。

**建议调整**：

#### `5.1 Backbone selection`
- 不要只把它写成工程选型；
- 强调最终选择某个 backbone 的依据，是它对后续搜索更重要的局部误差与排序可靠性，而不是单纯某个全局数值最好。

#### `5.2 Single-step prediction`
- 节首显式写出本节验证目标：如果 OFO 不能稳定学到局部响应，它就不应被拿来做搜索启发式；反之，则说明本文方法前提成立。

#### `5.3 Multi-step optimization`
- 正文分析建议显式分两层：
  - 与外部基线比较：证明本文路线有效；
  - 在 OFO family 内部比较：证明“单步模型 + 搜索”优于“单步模型 alone”。
- 这样能更清楚地区分“方法是否先进”与“搜索模块是否必要”。

#### `5.4 Ablation`
- 消融最好逐条对应创新点，而不是只列几个变体。
- 建议至少覆盖：
  - 双分支几何编码是否必要；
  - 操作条件是否必要；
  - 增量建模是否优于绝对性质建模；
  - OFO prior 是否必要；
  - leaf value 是否必要；
  - 剪枝/约束策略是否必要。

#### `5.5 Case study`
- 补成真实案例，而不是停留在计划型描述。
- 每个案例应尽量提供“分子—编辑—预测—选择—结果”的连续链条。

#### `5.6 Discussion and limitations`
- 建议在实验章末尾单独加一节，避免把所有讨论都压到结论里。

**目标**：让实验章形成清晰的闭环：

- 局部响应可学；
- 局部响应可用于搜索；
- 搜索确实有效；
- 关键模块为什么有效；
- 方法边界在哪里。

### 4.6 `6-conclusion.md`

**当前状态**：收束自然，但承担了过多“讨论”职能。

**建议调整**：

- 结论重点回收三件事：
  - 提出 OFO 建模单步编辑响应；
  - 将 OFO 统一转化为 MCTS 的多步搜索信号；
  - 在单步与多步实验中验证其有效性。
- 局限与未来工作保留，但适当压缩；更细的讨论前移到实验章末尾。

**目标**：让结论更像“贡献闭环”，而不是“结论 + 半个讨论”。

## 5. 推荐的最终章节结构

若希望更贴近 `TransDLM` 的成熟行文风格，建议采用如下结构：

1. Introduction  
2. Related Work  
3. OFO: Single-step Editing Response Prediction  
4. OFO-guided MCTS for Molecular Optimization  
5. Experiments  
   - 5.1 Backbone selection  
   - 5.2 Single-step prediction  
   - 5.3 Multi-step optimization  
   - 5.4 Ablation  
   - 5.5 Case study  
   - 5.6 Discussion and limitations  
6. Conclusion  

说明：

- 不一定非要单独新增一个大“理论分析章”；
- 如果篇幅有限，建议把“机制分析”放到第 3/4 章末尾，把“局限讨论”放到实验章末尾；
- 这样既不破坏现有骨架，又能显著提升论文成熟度。

## 6. 如果只做最小改动，优先级建议

### 优先级 1：统一全文主论点
在引言、相关工作、方法、实验和结论中，统一使用“局部编辑响应”这一核心表达，避免各章用不同说法分散主线。

### 优先级 2：补机制解释
至少补清三点：

- 为什么建模增量；
- 为什么排序可靠性比单纯回归误差更重要；
- 为什么 OFO 可自然转化为搜索启发式。

### 优先级 3：补实案例研究与局限讨论
这是当前最能提升完成度和说服力的部分。

---

## 7. 一句话结论

这套稿件当前已经具备较好的方法论文骨架；下一步最值得做的，不是大改结构，而是围绕“局部编辑响应”这一中心概念，把**问题定义、机制解释、实验验证、案例分析与局限讨论**进一步压成一条更完整、更锋利的论证链。
